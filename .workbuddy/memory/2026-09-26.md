### 关键技术决策

1. **零运行时依赖**：WBI 签名、设备指纹（含 bili_ticket）、protobuf 弹幕解析全部自实现。
   MD5 因 Web Crypto 不支持而手写在 `src/lib/md5.ts`，用 RFC 1321 官方向量做回归。
2. **不做本地 BV↔AV 互转**：B 站 view 类接口都同时接受并回传两者，本地转换只会引入难验证的 bug。
3. **CORS 自己实现**而非用 `hono/cors`：中间件后置代码在处理器抛错时不执行，会导致错误响应缺 CORS 头。

### 踩坑与修复（都已写入 AGENTS.md）

- **本机 pnpm isolated 链接模式失效**：`node_modules/.pnpm` 包齐全但顶层符号链接全缺，
  `pnpm install` 报告成功却 `Cannot find module 'hono'`。改为 `nodeLinker: hoisted`
  （pnpm 11 的配置写在 `pnpm-workspace.yaml` 而非 `.npmrc`），且切换前必须用 PowerShell 删掉 node_modules
  （bash 的 `rm -rf` 会被 safe-delete 守卫拦下，导致 pnpm install 静默失败）。
- **风控三级演进**：只有 WBI 签名 → `-352 风控校验失败`；补 buvid3/buvid4/b_lsid/_uuid/buvid_fp →
  `-412 request was banned`；再补 **bili_ticket**（HMAC-SHA256 申请）→ 成功。
- **两类「伪成功」响应**（静默错误答案，最容易漏）：
  ① 搜索返回 `code=0` 但只有 `v_voucher`；
  ② 空间投稿返回 `code=0` 但 `vlist:[]`、`count=0`（与「真的没投稿」结构完全相同，无法区分）。
  前者硬判错（-412），后者因无法区分而附加 `meta.warning`，并在冒烟测试里断言该告警必须存在。
- **上游字段陷阱**：`playurl.format` 是遗留值（DASH 下也返回 `flv720`，必须按实际流结构判定）；
  搜索结果数组叫 `result`（单数）；搜索 `duration` 是 `"12:34"` 文本；空间投稿时长字段是 `length: "04:28"`。
- **调试手法**：Node 原生 TS 剥离不支持无扩展名相对导入，故用 esbuild 把
  `scripts/debug-upstream.ts` 打成一个 mjs 再跑，就能复用 `src/lib` 的签名逻辑直接打上游看原始响应 ——
  这套夹具是定位上面所有字段/风控问题的决定性工具（已固化为 `pnpm debug:upstream`）。
