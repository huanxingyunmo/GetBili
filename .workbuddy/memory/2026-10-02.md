## Vercel 构建第二轮失败（TS2304）与根治（commit 503e92d）

第一轮修复（c51d9bf，去掉 @cloudflare/workers-types 强引用）后，Vercel 报新错误：
`src/types.ts(32,15): error TS2304: Cannot find name 'KVNamespace'`。

**新根因（重要机制差异）**：Vercel 用 TS7 从 `api/index.ts` 入口**沿 import 依赖图**构建类型检查程序，
无人 import 的全局 `.d.ts` 声明（src/cf-types.d.ts）不在程序内 → 全局名解析不到。
本地 `tsc --noEmit` 走 tsconfig.include 全集（含所有 .d.ts）所以通过——「本地绿、Vercel 红」。

**根治**：类型彻底模块化——`src/types.ts` 新增导出接口 `MinimalKV`（get/put 最小 KV 面），
`POLICY_KV?: MinimalKV`；删除 src/cf-types.d.ts。类型随 import 链传递，零全局声明、零平台专有包。

**经验**：跨平台项目类型契约必须「随 import 链可达」，不要依赖全局 .d.ts 或 compilerOptions.types。

## Vercel 构建失败修复（TS2688，第一轮）

用户在 Vercel（GitHub 集成）部署时报错：`error TS2688: Cannot find type definition file for '@cloudflare/workers-types'`。

**根因**：tsconfig 的 `compilerOptions.types` 强引用 `@cloudflare/workers-types`（devDependency），但 Vercel 构建环境的 pnpm 安装集没有包含它（日志 `Packages: +41`，本地全量应远多于此），TypeScript 直接构建失败。

**修复**（commit `c51d9bf`）：
- `src/cf-types.d.ts`（新建，后被 503e92d 删除并模块化进 types.ts）
- `tsconfig.json`：`types: []`；`lib` 增加 `DOM, DOM.Iterable` —— Web 标准 API 类型改由 lib 提供
- `package.json` + lockfile：移除 `@cloudflare/workers-types`（连带卸掉 76 个包）
- **验证**：typecheck 0 错误、MD5 回归 8/8、本地 Node 直跑 health 200 + 未登录 `/` 伪装 404 正常
