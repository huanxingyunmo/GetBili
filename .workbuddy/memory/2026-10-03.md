## Docker 自托管部署适配（commit 08b9654，主部署方式）

用户要求「改成docker部署样式」。Docker 跑在自己服务器/家宽上，出口 IP 干净，从根上绕开 B 站对 serverless 平台（Cloudflare 已实测全线 -412）的 IP 级风控。

**新增/修改**：
- `scripts/server.ts`（新）：生产入口。与 dev-node.ts 同构但**监听 0.0.0.0**（容器内绑 127.0.0.1 端口映射后外部无法访问——Docker 第一坑），PORT/HOST 可覆盖；.dev.vars 仅兼容加载（容器内无此文件静默跳过）
- `Dockerfile`（新）：两阶段构建——corepack pnpm@11.9.0 install（与 lockfile 生成端一致）→ esbuild bundle `scripts/server.ts` → `dist/server.mjs`（~244KB 自包含单文件）→ 运行阶段仅 node:22-alpine + 单文件（零 node_modules）；内置 HEALTHCHECK 打 /api/health
- `.dockerignore`（新）：**.dev.vars/.env 绝不进镜像**（敏感）
- `docker-compose.yml`（新）：.env 直读 + 环境变量注释齐全
- `src/lib/auth.ts`：Set-Cookie 的 Secure 硬编码改为 `COOKIE_SECURE` 环境变量控制（默认 true）。**坑：裸 HTTP 自托管时浏览器拒存 Secure Cookie → /adm 登录静默失败**，此时必须 COOKIE_SECURE=false；`clearSessionCookieValue(env?)` 同步适配 logout
- `src/types.ts`：Env += COOKIE_SECURE；package.json += build:node/docker:build/docker:run

**验证（本机无 Docker 的等价验证法）**：`pnpm build:node` 后 `node dist/server.mjs` 与容器内运行是同一份产物同一语义——实测 health 200 / 未登录伪装 404 / 错误 token 401 / 登录 Set-Cookie 两态（默认带 Secure；COOKIE_SECURE=false 无 Secure）全部符合预期；smoke 38/38 全绿。

**给用户的部署路径**：项目根建 .env（ADMIN_TOKEN/BILI_COOKIE/COOKIE_SECURE=false）→ `docker compose up -d --build`（或 `pnpm docker:build && pnpm docker:run`，后者用 .dev.vars + COOKIE_SECURE=false）。

## 部署方式演进史（跨平台适配要点沉淀）

Cloudflare Workers（-412 IP 风控）→ Vercel Edge（TS7 依赖图类型检查踩坑两轮，见 10-02 日志）→ **Docker 自托管（当前主方式）**。三平台共用 `src/index.ts` 单一业务源，env 注入语义统一为 `app.fetch(req, env)`：
- Workers：wrangler 绑定对象；Vercel/Node：process.env
- 策略存储三后端：Upstash REST > CF KV > 实例内存
- 类型契约必须「随 import 链可达」（MinimalKV 模式），勿依赖全局 .d.ts 或平台专有类型包

## 伪造 IP 头实验（2026-10-04 追加，commit b8d7343）

分析 NeteaseCloudMusicApiEnhanced/api-enhanced 的绕过机制（读到实锤代码）：
- **网易服务端信任 X-Real-IP/X-Forwarded-For 头**；它从 data/china_ip_ranges.txt（真实中国 CIDR 表）加权随机生成中国 IP（generateRandomChineseIP，global.cnIp 每进程一个），server.js 按 randomCNIP/req.ip 选择后传给 util/request.js 注入双头
- 本项目移植：src/lib/upstream.ts 的 applyFakeCnIp()（内嵌 23 条中国主干 CIDR 加权随机 + 模块级缓存），FAKE_CN_IP 开关；buildHeaders 与 fingerprint.ts 三处裸 fetch 全覆盖——**所有上游请求必须同一 IP，真假混用等于自报伪装**（本地 echo 服务器验证 6 类请求 100% 注入）
- **CF 线上 A/B 实测：关闭态 3/3 -412，开启态 3/3 -412 → B 站不信任这两个头，伪造无效**
- 根本差异：网易风控是「地域标签」（改头即可），B 站是「出口信誉」（TCP 对端 IP，必须真换出口）
- 代码保留默认关闭（零副作用，smoke 38/38），供未来网关行为变化复测；结论已写入 wrangler.toml 注释 / README / AGENTS.md
- **经验：跨站点风控手法不能想当然移植，「头可否伪造」唯一判定法 = 脏 IP 出口上的 A/B 实验**
